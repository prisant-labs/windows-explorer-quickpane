# QuickPane 3.10.0.8 (fork)

QuickPane 3.10.0.8 makes folder clicks respond without waiting for background work, and cuts the work QuickPane does while you are not using it. It also carries the Windows 11 tabs fix from 3.10.0.7, which was prepared but never published.

## At a glance

| Change | What you will notice | Tracked in |
|---|---|---|
| Clicks follow the tab in front | In a Windows 11 window with several tabs, a folder click opens in the tab you are looking at, and Recent records that tab's folder. | [#35](https://github.com/prisant-labs/windows-explorer-quickpane/issues/35) |
| Clicks never wait in line | A folder click no longer waits for a Recent check, an offline-path probe, or a large drag-and-drop copy to finish first. | [#38](https://github.com/prisant-labs/windows-explorer-quickpane/issues/38) |
| Browse never freezes | "Browse..." in Edit path, and every folder picker, open within about a second even when the old path is on a network share that does not answer. | [#41](https://github.com/prisant-labs/windows-explorer-quickpane/issues/41) |
| Faster start on network profiles | A groups folder on a slow or unreachable share no longer holds up startup and the tray icon. | [#42](https://github.com/prisant-labs/windows-explorer-quickpane/issues/42) |
| Less background work | Fewer cross-process calls into Explorer, fewer duplicate window events, fewer disk writes, and caches that stop growing. Nothing to see; the work just stops. | [#39](https://github.com/prisant-labs/windows-explorer-quickpane/issues/39), [#40](https://github.com/prisant-labs/windows-explorer-quickpane/issues/40), [#43](https://github.com/prisant-labs/windows-explorer-quickpane/issues/43) to [#50](https://github.com/prisant-labs/windows-explorer-quickpane/issues/50) |

## Fixed

**Windows 11 tabs: clicks went to the first tab.** In an Explorer window with more than one tab, clicking a folder in the pane opened it in the window's first tab instead of the tab on screen. The Recent section also recorded the first tab's folder instead of the one you were viewing. Both now follow the tab in front. This fix was built for 3.10.0.7, which was never published.

**Folder clicks waited for unrelated work.** Every folder click shared one background thread with the Recent check that runs every 2 seconds, checks of whether pinned paths are online, drive lists, drag-and-drop copies and moves, and the update check. A click that arrived while one of those ran waited for it, for seconds behind a large copy or an offline network path. Folder clicks in Explorer windows, file dialogs, and the desktop dock now have a thread of their own.

**Browse froze on an unreachable share.** When a pin pointed at a network share that did not answer, "Browse..." in Edit path froze the pane, and Explorer with it, for the network timeout. It did so twice, and a disconnected mapped drive timed out once for every level of the path. Each check now gives up after a second, and the picker opens without a starting folder.

## Changed

- **Startup.** QuickPane reads the groups folder in the background at startup and when you change the groups folder setting. Pins appear a moment after the pane does.
- **Recent.** The 2-second check of the Explorer window in front compares the window's title and front tab with the last check, and queries Explorer only when one of them changed, or every 30 seconds otherwise. It used to query every open Explorer window every time.
- **Single-tab windows.** In a window with one tab, a folder click and the Recent check stop at the first matching Explorer window instead of reading the list of every open tab.
- **Window events.** QuickPane installs each system-wide window event hook once and shares it. Window moves anywhere on the desktop used to reach QuickPane twice, and focus changes three times.
- **Finding Explorer windows.** The once-a-second check for new Explorer windows asks Windows for them directly, instead of reading the class name of every window on the desktop.
- **Layout.** Each layout pass walks a window's tabs once instead of two or three times.
- **Log files.** The log keeps its files open instead of opening and closing a file for every line. Each line still reaches the disk at once, and the files can still be opened in an editor while QuickPane runs.
- **Icon cache.** When the shared icon cache is full, it drops only the icons used longest ago, instead of emptying and making every visible row load its icon again.
- **Offline-path record.** The record of which paths exist, used to dim offline pins, holds at most 4,096 paths. It used to keep every path it ever saw for as long as QuickPane ran.
- **Groups folder watcher.** The groups folder is rescanned only for changes that can alter the groups. Write-time changes on folders, and on files such as `desktop.ini`, no longer each set off a rescan of every pin.
- **Crash guard.** The heartbeat file is rewritten when QuickPane's recorded activity changes, or once a minute when idle, instead of every 4 seconds all day.

## Still open

These came out of the same performance review and are not in this release:

- [#51 (every settings change rebuilds every pane)](https://github.com/prisant-labs/windows-explorer-quickpane/issues/51) is deferred. It touches every section of the pane, and no measurement yet shows the rebuild matters.
- [#52 (memory over a working day)](https://github.com/prisant-labs/windows-explorer-quickpane/issues/52) needs a day of readings on a real desktop. In Windows Sandbox, opening and closing seven Explorer windows twelve times left memory returning to the same level after each garbage collection, so closed windows do not leak.
- [#53 (the occasional busy cursor)](https://github.com/prisant-labs/windows-explorer-quickpane/issues/53) needs sightings matched against a capture on a real desktop. A folder click in the pane starts no process and never sets the cursor.

## For developers

- `WorkQueue` has two background lanes, `Post` and `PostNavigation`, built on a tested `WorkLane` type.
- `WinEventHook` keeps its API and shares native hooks through `WinEventHub`.
- New shared types: `LruCache` for capped caches, `AppendOnlyFile` for the log, and `PathStatus.FolderExistsWithin` for checks the UI must wait for.
- The test suite grew from 78 to 126 tests.
- The "Traps in the code" table in [docs/DEVELOPMENT.md](https://github.com/prisant-labs/windows-explorer-quickpane/blob/main/docs/DEVELOPMENT.md) gained rows for threads, bounded checks, hooks, Recent tracking, logging, and caches. [AGENTS.md](https://github.com/prisant-labs/windows-explorer-quickpane/blob/main/AGENTS.md) carries the same rules for coding agents.

## Install

Download `QuickPane-3.10.0.8-x64-setup.exe` and run it. It installs for the current user, with no administrator rights. Over an existing QuickPane, including one installed by the original project's installer, it closes QuickPane, replaces the program, and updates the same Add/Remove Programs entry. Your settings, groups, and pins in `%APPDATA%\QuickPane` stay where they are.

The zip holds the same program, for replacing the files by hand instead:

1. Close QuickPane, and wait for it to finish: `Start-Process "$env:LOCALAPPDATA\QuickPane\QuickPane.exe" -ArgumentList '--exit' -Wait`
2. Keep a copy of the current `QuickPane.exe` in `%LOCALAPPDATA%\QuickPane`, so you can go back.
3. Unzip the download, and copy `QuickPane.exe` and `QuickPane.exe.config` into `%LOCALAPPDATA%\QuickPane`, replacing the files there.
4. Start `%LOCALAPPDATA%\QuickPane\QuickPane.exe` again.

`SHA256SUMS.txt` lists the SHA-256 hash of the installer, the zip, and each file inside the zip. The files are not code-signed, so Windows SmartScreen may warn before the installer first runs. This release also carries a GitHub build provenance attestation, which `gh attestation verify <file> -R prisant-labs/windows-explorer-quickpane` checks.

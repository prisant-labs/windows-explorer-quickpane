# QuickPane 3.11.0.0 (fork)

QuickPane 3.11.0.0 replaces the Settings window's tabbed panel with a window that looks and behaves like a page of the Windows 11 Settings app: a navigation pane, a search box, cards, and a Mica backdrop. The pane that lives inside File Explorer is unchanged. The redesign followed a written spec and plan, built as nine changes, one per issue, [#89](https://github.com/prisant-labs/windows-explorer-quickpane/issues/89) to [#97](https://github.com/prisant-labs/windows-explorer-quickpane/issues/97).

## Why

The pane and Settings are two different surfaces. The pane lives inside someone else's window, all day, and must match Explorer. Settings is QuickPane's own window, opened now and then, and can look and feel more like a modern Windows app. The redesign, specced and planned on 2026-10-30, builds Settings to that second standard without touching the pane's code, look, or behavior at all.

## Added

**A native Settings shell.** `SettingsWindow` replaces `SettingsPanel`'s tab strip with a navigation pane (seven pages, with About pinned at the bottom), a search box that jumps straight to a matching setting, a breadcrumb above the content area for sub-pages such as a single profile or SSH connection, and a Mica backdrop on Windows 11. Windows 10, or a Mica failure, falls back to a standard window frame.

**The Fluent visual style, ported and scoped to Settings.** The window's cards, buttons, and other controls use a port of Microsoft's WPF Fluent theme, which ships with .NET 9 as `PresentationFramework.Fluent`. `FluentThemeService` merges the port into the Settings window's own `Resources` only, never into `Application.Current.Resources`, so the pane inside Explorer keeps its existing look. A unit test checks that no Fluent dictionary ever reaches the application level. See [`QuickPane/Themes/Fluent/NOTICE.md`](../../QuickPane/Themes/Fluent/NOTICE.md) for the source commit, the licence, and what QuickPane changed to build it on .NET Framework 4.8.

**Eight pages.** Groups & profiles, Pane, Pane sections, Recent apps, Keyboard, Backup & restore, SSH drives, and About each read and write the same settings fields the old tabs did, with the same values and the same validation. Every page is reachable from the navigation pane and from search.

**Accessible by keyboard and screen reader.** Every control carries an accessible name. Tab and the arrow keys move through the navigation pane, then the open page, in reading order, with a visible focus ring on every control, including the breadcrumb.

## Changed

- **The update check.** It now runs only when the About page opens, or when you press "Check for updates" there, instead of every time Settings opens.
- **Reordering and moving groups.** A profile's groups are now reordered with Move up and Move down buttons, and moved to another profile with an inline destination picker and a "Copy instead of move" checkbox, instead of dragging a group between columns.
- **Reordering pane sections.** Pane sections are now reordered with Move up and Move down buttons instead of dragging a row.
- **Renaming and removing a profile.** These are now an inline text box with a Save button, and a confirm row, instead of a double-click and a message box.

## Not changed

- **The pane.** Nothing in `QuickPane/Explorer/` or any pane section changed. `QuickPane/Interop/NativeMethods.cs` gained one declaration, for the Mica backdrop, which only the Settings window uses. The pane takes no code from the Fluent port and no third-party UI library.
- **`settings.json`.** No field was added, renamed, or removed. Every Settings page reads and writes the same fields the old tabbed panel did.

## Still open

- Whether Settings needs its own UI thread. [#97](https://github.com/prisant-labs/windows-explorer-quickpane/issues/97) adds logging for how long Settings takes to open and to switch pages. The sandbox measured Settings opening in 451 to 503 ms against the 500 ms budget, close enough either way that the sandbox number does not decide it. The deciding measurement is a real desktop: the "SettingsWindow: opened in N ms" log line from the draft build, run on a real desktop rather than in the sandbox. If that line reads over 500 ms, Settings moves onto its own UI thread before 3.11.0.0 is published.
- Whether Windows Sandbox renders Mica. If it does not, only a real desktop test can confirm the backdrop.
- Settings does not remember its window size or position across restarts. This was unchanged before the redesign too.

## For developers

- The Settings window's code now lives under `QuickPane/UI/Settings/`: `SettingsWindow.cs` (the shell), `SettingsCards.cs` (shared card builders), `SettingsSearch.cs` (the search index), and `Pages/*.cs` (one file per page). `QuickPane/UI/SettingsPanel.xaml` and `SettingsPanel.xaml.cs` are gone.
- Every page implements `SettingsPage` (`Id`, `Title`, `Glyph`, optional `SearchEntries`, and `Build(SettingsPageContext)`). `Build` must do no disk, network, or COM work itself; anything slow goes through `WorkQueue` first, exactly as `AGENTS.md` already requires elsewhere.
- `docs/DEVELOPMENT.md` has the full page contract, how to update the Fluent port from a newer `dotnet/wpf` commit, and the rule that Fluent styles stay in the Settings window's own resources.
- The test suite grew from 171 to 251 tests across the redesign.
- Release `QuickPane.exe`: 689,152 bytes in 3.10.0.11, 958,976 bytes now, a growth of 269,824 bytes (about 264 KiB), inside the spec's 1 MB budget.

## Install

Download `QuickPane-3.11.0.0-x64-setup.exe` and run it. It installs for the current user, with no administrator rights. Over an existing QuickPane, including one installed by the original project's installer, it closes QuickPane, replaces the program, and updates the same Add/Remove Programs entry. Your settings, groups, and pins in `%APPDATA%\QuickPane` stay where they are.

The zip holds the same program, for replacing the files by hand instead:

1. Close QuickPane, and wait for it to finish: `Start-Process "$env:LOCALAPPDATA\QuickPane\QuickPane.exe" -ArgumentList '--exit' -Wait`
2. Keep a copy of the current `QuickPane.exe` in `%LOCALAPPDATA%\QuickPane`, so you can go back.
3. Unzip the download, and copy `QuickPane.exe` and `QuickPane.exe.config` into `%LOCALAPPDATA%\QuickPane`, replacing the files there.
4. Start `%LOCALAPPDATA%\QuickPane\QuickPane.exe` again.

`SHA256SUMS.txt` lists the SHA-256 hash of the installer, the zip, and each file inside the zip. The files are not code-signed, so Windows SmartScreen may warn before the installer first runs. This release also carries a GitHub build provenance attestation, which `gh attestation verify <file> -R prisant-labs/windows-explorer-quickpane` checks.

# QuickPane 3.10.0.2 (fork)

QuickPane 3.10.0.2 is the first published release of the [prisant-labs/windows-explorer-quickpane](https://github.com/prisant-labs/windows-explorer-quickpane) fork. It builds on [QuickPane 3.10.0](https://github.com/lso2/QuickPane/releases/tag/QuickPaneSetup-3.10.0-release) by lso2. It adds eight changes you can see, and a test and build foundation for anyone working on the code.

Version 3.10.0.1 was prepared but never published. Everything it contained is in this release.

## Fixed

**Windows 11 tabs.** In a Windows 11 Explorer window with more than one tab, QuickPane moved only one tab aside to make room for the pane. Every other tab stayed at full width. Depending on which window was on top, either the pane covered Explorer's own sidebar, or the tab covered the pane. Every tab now makes room, including tabs opened later. The layout also keeps working after you close the first tab. Windows 10 has no Explorer tabs, so it never had this problem.

**"Add folder..." and "Add file..." on a tab.** In a group with more than one tab, there was no way to add a folder or file from a tab's right-click menu. The tab menu now has both commands, and the new pin lands in that tab.

**"Delete tab" asks first.** "Delete tab" used to erase the tab and its pins at once, with no warning and no way back. It now asks first when the tab holds pins, and it sends the tab's folder to the Recycle Bin, as "Delete group" already did.

**Profile row with one profile.** The pane used to show its profile row even with only one profile. The row held a single "Profile 1" button that switched nothing. The row now appears once a second profile exists. A note under Settings, Pane, Profile tabs explains this.

## Added

**A "File dialogs" setting.** It is on the Pane tab of Settings, under "File dialogs":

- **Same as Explorer windows** is the default, and it keeps the original behavior: dialogs follow the Pane mode setting.
- **Beside the dialog** puts the pane next to an Open or Save dialog instead of inside it.
- **Off** keeps the pane out of dialogs entirely. App Folders and "Always start here" only exist in dialog panes, so Off hides them too.

**A "Browse..." button in "Edit path".** Right-click a pinned folder or file and choose "Edit path". The new button opens a picker at the pin's current location, so you no longer have to type the path.

## Changed

**Modern folder picker.** "Add folder..." and the "..." button for a profile's groups folder now open the Explorer-style folder picker. It has the address bar, search box, and navigation pane that the old "Browse For Folder" tree lacked.

**The update notice follows this fork.** The Settings footer now checks this fork's releases, not the original project's. The original project's installer would replace this fork's program, and every change above would be lost. The notice also shows a fork version's fourth number, such as 3.10.0.2.

## For developers

- A unit-test project, `tests/QuickPane.Tests`, with 61 tests of the app's decision logic. They run without showing any windows.
- `scripts/build.ps1` and `scripts/test.ps1` build the app and run the tests. They work with or without the .NET Framework 4.8 targeting pack installed.
- A GitHub Actions workflow builds the app and runs the tests on every push and pull request. `main` accepts changes only through a pull request whose build and tests passed.
- [docs/DEVELOPMENT.md](https://github.com/prisant-labs/windows-explorer-quickpane/blob/main/docs/DEVELOPMENT.md) covers building, testing, the code's known traps, working with the original project, and releasing. [AGENTS.md](https://github.com/prisant-labs/windows-explorer-quickpane/blob/main/AGENTS.md) holds the same rules for coding agents.

## Install

This release ships the program, not an installer. It replaces the program file inside an existing QuickPane installation.

**If QuickPane 3.10.0 is not installed yet,** install it first with `QuickPaneSetup-3.10.0-release.exe` from the [original project's release](https://github.com/lso2/QuickPane/releases/tag/QuickPaneSetup-3.10.0-release). The installer sets up the startup entry, the Start menu entry, and the "Pin to Quick Pane" folder command. All three keep working after the program file is replaced.

**To upgrade,** run these steps in PowerShell:

1. Download `QuickPane-3.10.0.2-x64.zip` and `SHA256SUMS.txt` from this release.
2. Close QuickPane, and wait for it to finish:
   `Start-Process "$env:LOCALAPPDATA\QuickPane\QuickPane.exe" -ArgumentList '--exit' -Wait`
   Closing it this way, or with Exit on the tray icon, lets it restore your Explorer windows' layout. Do not end it from Task Manager.
3. Keep a copy of the current program, so you can go back:
   `Copy-Item "$env:LOCALAPPDATA\QuickPane\QuickPane.exe" "$env:LOCALAPPDATA\QuickPane\QuickPane.exe.bak"`
4. Unzip the download, and copy `QuickPane.exe` and `QuickPane.exe.config` into `%LOCALAPPDATA%\QuickPane`, replacing the files there.
5. Start `%LOCALAPPDATA%\QuickPane\QuickPane.exe`. The Settings window's footer should show 3.10.0.2.

Your settings, groups, and pins live in `%APPDATA%\QuickPane`. The upgrade leaves them where they are.

## Check the download

`SHA256SUMS.txt` lists the SHA-256 hash of the zip and of each file inside it. To check the zip, run `Get-FileHash .\QuickPane-3.10.0.2-x64.zip` and compare the result with the zip's line in `SHA256SUMS.txt`. The two must match exactly.

## Go back to the previous version

1. Close QuickPane with the same `--exit` command as in step 2 above.
2. Copy `QuickPane.exe.bak` back over `QuickPane.exe` in `%LOCALAPPDATA%\QuickPane`.
3. Start QuickPane again.

Your settings carry over in both directions. An older version ignores the "File dialogs" choice, and it drops that choice the next time it saves its settings. After upgrading again, set it once more.

## Known limitations

- **The files are not code-signed.** Windows SmartScreen may warn before the program first runs. If Windows blocks the files, right-click the zip, choose Properties, select Unblock, and unzip it again.
- **Add/Remove Programs still shows 3.10.0,** because the version there comes from the installer, not the program file.
- **A tab can flash briefly** when you open or close it. Explorer itself stretches every tab back to full width at that moment, and QuickPane moves them back, usually within a tenth of a second. Switching between tabs does not flash.
- **The keyboard shortcut does nothing in Explorer windows.** The shortcut that should move focus into the pane works only in file dialogs. This is an open bug in the original project, [lso2/QuickPane#4](https://github.com/lso2/QuickPane/issues/4), and this release does not fix it.
- **Running the original project's installer later** replaces this fork's program with the original. To come back, repeat the upgrade steps.

## How this release was tested

- All 61 unit tests passed locally, and in CI on every pull request.
- Each fix and each new control was exercised in Windows Sandbox, a disposable copy of Windows, using invented demo folders. Scripted clicks drove the pane, and screenshots recorded the result.
- The Windows 11 tabs fix passed a scripted check that opens, switches, closes, restores, and maximizes tabs. The same check failed on the earlier build, which shows it really detects the bug.
- The update notice's version handling has unit tests. No automated test reaches GitHub itself.
- A check on a real Windows 11 desktop is required before a fork release is published.
